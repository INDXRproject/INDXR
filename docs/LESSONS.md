[2026-05-17] supabase-ssr: Gebruik getClaims() in middleware, niet getUser(). getClaims() returnt null bij geen sessie zonder retry-loop en zonder Supabase-netwerk-calls. getUser() maakt een server-side validatie-call en kan refresh-loops triggeren bij stale tokens (bewezen: 500K Upstash commands in 5 dagen, commit 22a0059). Voeg GEEN error-recovery cookie-clearing toe in middleware — clearAuthCookies() wist ook PKCE code-verifier (sb-*-auth-token-code-verifier), waardoor exchangeCodeForSession() faalt in OAuth/email-callback flows. Volg het officiële Supabase Next.js template letterlijk (vercel/next.js with-supabase).
[2026-05-17] supabase-ssr: Sluit auth callback routes uit van updateSession middleware via de matcher. Routes met exchangeCodeForSession() (bijv. /auth/callback) creëren zelf een sessie en hebben geen session-refresh nodig. updateSession() op een callback route kan de tijdelijke PKCE verifier-cookie verwijderen vóór de exchange → silent failure. Voeg auth/callback toe als uitzondering in de middleware matcher.

[2026-05-05] next-server-actions: window.location.href na await serverAction() veroorzaakt "Error in input stream" TypeError omdat de browser de RSC action-response stream aborteert mid-transmission (Next.js GitHub #81377) → nooit window.location.href of router.push na een Server Action aanroep; gebruik redirect() in de Server Action zelf voor cross-host navigatie.
[2026-05-05] subdomain-split: redirect("/<auth-path>") in Server Components op app.indxr.ai veroorzaakt 307 → middleware 308 → cross-origin chain die RSC prefetch parser breekt → TypeError "Error in input stream". [2026-05-05] cross-host-links: audit cross-host links op drie patronen, niet alleen <Link>: (1) `<Link href="/pad">`, (2) `<a href="/pad">`, (3) `window.location.href = '/pad'`. Alle drie vereisen appHref()/marketingHref() wanneer de component op een andere host gerenderd kan worden.
[2026-05-05] env-vars: vermijd meerdere env-var-namen voor hetzelfde concept (NEXT_PUBLIC_SITE_URL naast NEXT_PUBLIC_APP_URL + NEXT_PUBLIC_MARKETING_URL is verwarrend). Eén concept = één var. Bij subdomain-split: NEXT_PUBLIC_APP_URL voor app-host, NEXT_PUBLIC_MARKETING_URL voor marketing-host.
[2026-05-05] vercel-limits: directe browser→Railway POST voor audio uploads omzeilt Vercel's 4.5MB request body limiet (AudioTab.tsx). Noem de env-var expliciet NEXT_PUBLIC_AUDIO_UPLOAD_URL zodat het doel helder is — niet NEXT_PUBLIC_PYTHON_BACKEND_URL hergebruiken voor dit specifieke geval.
[2026-05-05] git-workflow: CC heeft git commit uitgevoerd zonder expliciete toestemming → CC voert NOOIT git add/commit/push uit zonder expliciete toestemming per taak. Khidr geeft commit-toestemming in de taakprompt of in een vervolgbericht.
[2026-05-06] vercel-env-vars: Sensitive env vars kunnen NIET op alleen Development scope worden gezet — Vercel forceert minstens Production of Preview voor sensitive vars. De C.3.1 workaround (env vars op Development scope om noopLimiter te activeren in productie) is daarom niet herbruikbaar voor sensitive vars. Alternatief: vars volledig verwijderen om noopLimiter te activeren, of niet-sensitive maken.
[2026-05-06] vercel-env-vars: Vercel UI env var input accepteert GEEN quotes rond waardes. .env files gebruiken KEY="value" syntax maar in Vercel UI moet alleen de rauwe waarde, anders worden de quotes letterlijk deel van de string. Bij plak-uit-.env: quotes verwijderen.
[2026-05-06] ui-state: Twee parallelle UI-state mechanismen op hetzelfde concept (Shadcn useSidebar + custom localStorage voor sidebar breedte) zijn een recipe for desync — één knop doet visueel niets op desktop omdat hij de verkeerde state bestuurt. Kies één mechanism per UI-concept en verwijder de andere. Bij Shadcn-componenten met custom overrides: de custom state wint altijd; verwijder de Shadcn default trigger als die geen effect heeft.
[2026-05-07] shadcn-sidebar: Shadcn Sidebar `variant="inset"` (en alle non-collapsible="none" varianten) gebruikt `position: fixed; top: 4rem` — hardcoded 4rem header assumptie. Conflicteert met custom topbar heights. Gebruik `collapsible="none"` voor flex-flow integratie: sidebar zit dan in normale document flow, geen fixed positioning, hoogte bepaald door flex container. SidebarProvider moet OUTER wrapper blijven (context scope voor useSidebar hooks), layout-flex in geneste div erin.
[2026-05-07] react-context: Componenten die useContext() of custom hooks gebruiken (zoals Shadcn useSidebar()) MOETEN binnen de bijbehorende Provider rendered worden. Bij refactoring naar custom layout: SidebarProvider als outer wrapper laten, ook al stuurt hij visueel niet de hele layout. Provider = context scope, niet visuele container.
[2026-05-07] css-absolute-containment: Een `position: absolute` child van een `position: sticky` parent (bijv. Button inside sticky header) gebruikt de sticky parent als containing block. Maar zonder `overflow: hidden` op de sticky parent kan de absolute child buiten de button bounds verschijnen. Fix: altijd `relative overflow-hidden` op het directe parent element van een absolute-positioned child, niet alleen op een verre ancestor.
[2026-05-07] css-variables: Een CSS-variabele die zichzelf referentieert in een inline style (`style={{ "--x": "var(--x)" }}`) levert een guaranteed-invalid value op dat element. Child-elementen die `var(--x)` gebruiken krijgen 'invalid' terug en vallen terug op default (bijv. transparent voor kleuren). Patroon ontstaat bij mislukte pogingen om een Tailwind/Shadcn defaultkleur te overriden — gebruik in plaats daarvan een ANDERE CSS-variabele als bron, of een directe kleurwaarde.
[2026-05-17] cross-host-redirect: router.push('/pad') of router.push() in een component op een andere host dan het doelpad blijft op de huidige host → 404 op de ontbrekende route. Gebruik window.location.href = appHref('/...') (of marketingHref) voor cross-host navigatie. Next.js Link en router.push zijn altijd same-origin.
[2026-05-17] env-vars-vercel: BACKEND_API_SECRET mismatch tussen Vercel en Railway gaf 401 op alle backend API calls. Vercel UI accepteert geen quotes rond env values — letterlijke quotes worden opgeslagen als deel van de waarde. Bij elke env var: paste zonder aanhalingstekens, check scope (Production + Preview), redeploy zonder build cache om var op te halen. Var moet identiek zijn op alle Vercel projecten die de backend aanroepen (indxr-marketing + indxr-app). Na migratie naar nieuwe Vercel projecten altijd opnieuw verifiëren — env vars worden niet automatisch overgenomen.
[2026-05-17] supabase-recovery: PKCE-based recovery emails (password reset, magic link) moeten redirectTo instellen op een route die exchangeCodeForSession aanroept. Direct naar een protected app-pagina sturen werkt niet — de code vervalt en geeft otp_expired. Patroon: redirectTo = {marketing}/auth/callback?next=<encoded-final-target>; callback wisselt de code in en redirect dan naar final-target met hostname-validatie (voorkom open redirect).
[2026-05-17] upstash-arq: noopLimiter-pattern voor Upstash quota-mitigatie werkt op Vercel (env vars verwijderen → noopLimiter actief) maar NIET voor ARQ workers. ARQ roept bij init `pool.delete(self.health_check_key)` aan — zonder werkende Redis crasht de worker bij elke startup. Bij quota-incident: óf plan upgraden, óf worker offline nemen, niet "vergeten en doorgaan".
[2026-06-04] redis-serverless-vs-polling: Serverless per-commando Redis (Upstash) is structureel ongeschikt voor constant pollende workers. ARQ met `poll_delay=0.5s` + `health_check_interval=1s` genereert ~10.860 Redis-commando's/uur idle = ~7,84M/maand = 15,7× Upstash Free Tier (500K/maand) — zonder ook maar één job. Regel: gebruik container-Redis (Railway, geen kosten per commando) voor ARQ workers; gebruik Upstash alleen voor sporadische serverless calls (rate-limiter, cache). Het mismatch-probleem is niet configureerbaar weg via hogere poll_delay — health_check (1/s) domineert al bij poll_delay=5s.
[2026-06-27] playlist-shared-helper: bij playlist-jobs die een gedeelde helper aanroepen (bijv. do_assemblyai_transcription), verifieer dat cache-reads/guards in de helper zelf zitten en niet in een wrapper (run_whisper_job) die de playlist overslaat — anders mist één pad de optimalisatie stil zonder fout of log.
[2026-06-27] yt-dlp-tlang: `subtitleslangs` filtert `info['automatic_captions']` NIET in `extract_info(download=False)` mode — alle ~120 YouTube-vertaaltalen komen terug ongeacht de instelling. De enige betrouwbare manier om een native track te selecteren is: zoek sleutels die eindigen op `-orig` in `info['automatic_captions']` (bv. `ja-orig`) — die hebben nooit `tlang=` in de URL. Sleutels zonder `-orig` (bv. `en` voor een Japanse video) bevatten een machinevertaals-URL. Gebruik NOOIT de taalcode uit de YouTube Data API (`videos.list language`) als enige grondslag voor track-selectie: de API geeft `'en'` terug voor niet-Engelse video's (bewezen voor iKtPI8IMuOM, Japans). Verifieer altijd URL-niveau (`'tlang=' not in url`) als safety net.
[2026-06-04] tailwind-v4-monorepo: Tailwind v4 (@tailwindcss/postcss) scant NIET automatisch packages buiten de app-directory. In een monorepo met packages/shared/ moeten alle apps een `@source "../../../../packages/shared/src/**/*.{ts,tsx}";` directive toevoegen aan hun tokens.css (pad relatief ten opzichte van het CSS-bestand). Zonder dit ontbreken alle Tailwind utility classes die uitsluitend in shared components voorkomen (bg-accent, md:flex, md:hidden, text-fg-subtle, etc.) uit de CSS output — resulterend in onzichtbare UI elementen en kapotte responsive layouts.
[2026-06-30] supabase-migrations: 8-cijferige timestamp-prefixes (bijv. 20260302_) en SQL-Editor-wijzigingen buiten de CLI zijn onzichtbaar voor supabase_migrations.schema_migrations → schema-drift zonder foutmelding. Remedie: baseline-squash via Management API introspectie (pg_get_functiondef, pg_policies, information_schema, pg_constraint voor cross-schema FKs) → één baseline .sql in migrations/, tracking-reset via DELETE + INSERT op schema_migrations, pre-baseline bestanden naar migrations_archive/.
